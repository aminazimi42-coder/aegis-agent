GOAL
Lock the local operator page after idle so a stranger at the unlocked laptop cannot Approve/Reject/Propose/export without a local PIN. PIN lives in macOS Keychain on Darwin. CI uses an in-process mock. Core execute path never sees the PIN. Forget/purge must drop that tenant's lock material the same way other tenant stores drop.

IN SCOPE
1. Idle lock on the operator HTML page after a documented idle timeout (default 15 minutes, override AEGIS_SESSION_IDLE_SECONDS, min 60, max 86400).
2. Unlock only with local PIN verify. Wrong PIN typed fail. Lockout after 5 failures for 5 minutes, typed.
3. Store PIN verifier in Keychain service "aegis-operator-session" account "{tenant_id}" on Darwin. Never write the raw PIN to AEGIS_DATA_DIR, git, logs, audit JSONL, receipts, or propose text.
4. CI / non-Darwin: mock keychain module already used by T196 pattern. Tests must not need a real Keychain.
5. Start Session after cold start still works. If no PIN has been set, first-run page offers optional "Set session PIN" — not required to propose. If PIN is set, locked page blocks Propose/Approve/Reject/Export/Quit-engine until unlock.
6. Tests:
   - idle then lock; unlock with correct PIN; wrong PIN typed fail
   - neighbor tenant cannot unlock this tenant
   - Forget tenant drops Keychain/mock item for that tenant only
   - audit/propose/export contain no PIN digits
   - start_operator.sh still sole start; script does not open Safari
7. STATUS one honest paragraph. README Now may say "optional local session PIN" only if tests prove it. Do not claim biometrics. Do not claim Face ID.
